# PWA

## Purpose

This is what makes the web app installable on a phone. It owns the app icons, the launch screens
iPhone shows while the app opens, the home screen shortcuts, the browser theme colour, and the
Apple-specific tags iOS needs.

All of it is kept in one place so the manifest, the page head, and the script that generates the
image files can never disagree about which icons exist. `app/layout.tsx` pulls it into the page's
`metadata` and `viewport`.

Right now this covers installing only. The service worker, offline support, and push notifications
are planned in `docs/PLAN-PWA.md` and will live here too.

## Structure

- `constants/appIcons.ts` — which icons exist (192 and 512 pixels, in both normal and maskable
  form), the Apple icon size, the maskable safe area, and how a file name is built from those.
  Nothing anywhere else should ever write an icon file name by hand.
- `constants/appleSplashScreens.ts` — the list of iPhone and iPad screen sizes we ship launch
  images for, and how those file names are built.
- `constants/appShortcuts.ts` — the shortcuts that appear when you long-press the app icon.
- `constants/appTheme.ts` — the light and dark theme colours, copied from `--background` in
  `packages/design-system/tokens.css` so the app bar matches the app.
- `constants/appMetadata.ts` — the icon, Apple, and manifest parts of the page head.
- `utils/manifestIcons.ts` — turns the icon list into the manifest's format.
- `utils/appleSplashMedia.ts` — builds the media query that picks one launch image for one device.
- `utils/appViewport.ts` — the page's `viewport`, including the theme colour for light and dark.
- `components/AppleSplashLinks.tsx` — puts one launch image link in the page head per device.

The actual image files live in `public/icons/` and `public/splash/`. They are generated by
`apps/web/scripts/generate-pwa-assets.mts`:

```bash
pnpm --filter @outfiqe/web generate:pwa-assets
```

Run that and commit the output whenever `public/logo.svg` changes, or whenever an icon size or a
device is added to the lists above. The script reads those same lists, so an image can never be
missing for a device the app claims to support.

## How it works

**What the user sees.** On Android, the browser reads the manifest, sees a proper name, the
required icon sizes, and a maskable icon, and offers to install the app. On iPhone the user taps
Share and then Add to Home Screen; iOS uses the Apple icon for the home screen and shows the
matching launch image while the app opens, instead of a white flash. Once installed, long-pressing
the icon on Android shows the Shop, Explore, Search, and Wishlist shortcuts, and the phone's status
bar picks up the app's colour in both light and dark mode.

**What the code does.** `app/manifest.ts` builds the manifest from the icon list and the shortcut
list, and Next serves it at `/manifest.webmanifest`. `app/layout.tsx` takes the shared SEO
metadata and then overrides the manifest link, the icons, and the Apple settings from here.
`AppleSplashLinks` renders into the page head, turning each screen size in the list into a link
with the media query that selects it.

## Things that are not obvious

**`start_url` and `id` are different on purpose.** `start_url` is `/?source=pwa` so we can tell in
analytics when someone opened the installed app rather than the website. `id` stays as `/`. The
`id` is what browsers use to recognise the app, so if we ever change that query string, existing
installs still update instead of being treated as a brand new app.

**Launch images are portrait only.** Supporting landscape too would double 13 image files to 26 for
a shopping app people hold upright. Opening in landscape just shows the plain background colour
instead. Worth revisiting if iPad turns out to be popular.

**The maskable icon is a different image, not just a smaller one.** Android crops app icons into
whatever shape the phone uses — circle, squircle, rounded square — and throws away anything outside
the middle 80%. So the generator draws the logo smaller and places it on a full square of
background colour. Using the same image for both would get the logo's edges cut off on most phones.

**Icons moved out of `shared/seo`.** They describe the installed app, not the search result, and
keeping them next to the icon list is what lets the manifest, the Apple icon, and the generator
share one list. Everything genuinely SEO-related stayed where it was.
